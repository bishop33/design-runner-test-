# 준비 — 임신부터 출산 후 24개월까지

체크와 기록을 중심에 둔 임신·출산·육아 동반 서비스의 MVP입니다.
정보를 많이 보여 주는 앱이 아니라, **지금 무엇을 알아보고 무엇을 실행해야 하는지**를 알려 주고
**부부가 함께 완료 여부를 확인**하는 도구를 목표로 합니다.

### 데이터로 확인한 사실

- 한 구간(대시기+세부 시기)의 모든 행은 시점 기준·시작·종료·단위가 같습니다.
  → 타임라인에서 항목마다 날짜를 반복해 쓸 필요가 없어 **구간 헤더에만 날짜를 둡니다.**
- `알아보기 → 실행`이 시기를 건너뛰어 이어지는 일이 실제로 있습니다.
  산후도우미(임신 후기 알아보기 → 병원 회복 신청), 어린이집(출산 준비 알아보기 → 영아 중기 대기 확인),
  조리원(임신 중기 비교 → 임신 후기 가방 → 입원 직전 연락 → 조리원 퇴소).
  세부 주제가 중간에 바뀌므로 **`tools/sheet-to-content.py`의 `CHAIN_GROUPS`에서 묶어** 9개 흐름을 만듭니다.
- 개인화 조건에 걸린 행은 26개뿐입니다. 온보딩 답변으로 숨길 수 있는 범위가 크지 않으므로,
  **숨김보다 우선순위 조정**을 기본으로 둡니다.

## 2. 데이터 모델

원본과 사용자 상태를 완전히 분리합니다. 콘텐츠 파일에는 완료 여부·메모를 쓰지 않습니다.

```
tools/content.source.csv ──(sheet-to-content.py)──> app/data/content.json   읽기 전용
                                                            │
                                             app/src/model.js ── 합쳐서 화면용 목록 생성
                                                            │
                                        localStorage(junbi.state.v1)        사용자 상태
```

### 콘텐츠 (`app/data/content.json`)

- `meta` — 시기·주제·유형 순서, 행동 흐름 9개, 정규화 기록, 결측 통계
- `bands[20]` — 타임라인 구간. `{phase, band, anchor, start, end, unit}`
- `items[356]` — 시트 한 행 = 한 항목 + `typeGroup`, `conditionKey`, `related[]`, `chain`, `bandId`

### 사용자 상태 (`app/src/store.js`)

```js
{ schemaVersion, onboarded,
  profile: { 기준일 5개, 출산 방법, 상황 7개, members[2], activeMemberId, hideNonApplicable },
  items:   { [itemId]: { status, remindOn, doneAt, doneBy, gear, bags, updatedAt, updatedBy } },
  notes:   { [itemId]: [{ id, by, at, text }] },
  experiences: { [itemId]: [{ id, by, at, reaction, text }] },
  customItems: [...],
  activity: [{ at, by, itemId, title, kind, detail }] }
```

저장은 `loadState` / `saveState` 두 함수 뒤에 있고 모든 API가 async 라, DB로 옮길 때 이 두 함수만 바꾸면 됩니다.

### 날짜 계산 (`app/src/dates.js`)

| 기준 | 계산 |
|---|---|
| 임신 주차 | `출산 예정일 − 280일 = LMP`, `LMP + 주차×7` |
| 입원일 | 입력값. 비우면 `출산 예정일 − 1일`. 출생일이 더 앞서면 출생일로 당김 |
| 출생일 | 입력값. 없으면 출산 예정일(추정) |
| 조리원 입소일 | 입력값. 없으면 `출생일 + 3일`(추정) |
| 집 복귀일 | 입력값. 없으면 `조리원 입소일 + 14일`, 조리원 미이용이면 `출생일 + 3일`(추정) |

추정값은 화면에 "추정"으로 표시하고 설정에서 고칠 수 있습니다.
출생일이 입력되면 임신 주차 기준 항목의 구간은 출생일에서 끝난 것으로 봅니다.

### 우선순위

`중요도 + 상태 + 체크 가능 + 개인화 + 시기` 를 더한 점수로 정렬합니다.
지난 항목은 `70 − 지난일수×2`로 감쇠해서, 마감 직후엔 맨 위에 오고 2주쯤 지나면 잔소리가 되지 않습니다.
`지금 먼저 할 일`은 3~5개로 제한하고 지난 항목은 최대 2개까지만 넣습니다.

## 3. 화면과 흐름

| 화면 | 경로 | 역할 |
|---|---|---|
| 온보딩 | `#/onboarding` | 기준일 2개 + 상황 8개. 나머지는 건너뛸 수 있음 |
| 오늘 | `#/today` | 현재 상태 → 지금 먼저 할 일 → 미확인 중요 항목 → 곧 할 일 → 부부 기록 |
| 전체 타임라인 | `#/timeline` | 세로 20구간. 유형·주제 필터, 완료 숨기기, 구간 접기, 줄에서 바로 상태 변경 |
| 주제별 | `#/topics`, `#/topics/:주제` | 같은 원본을 주제 → 세부 주제로 |
| 항목 상세 | `#/item/:id` | 이유·시기·방법·비용·출처·상태·리마인드·메모·경험담·행동 흐름·관련 항목 |
| 검색 | `#/search` | 제목·주제·세부 주제·요약 |
| 직접 추가 | `#/custom` | 기본 목록에 없는 일을 구간·주제·중요도와 함께 추가 |
| 부부 활동 | `#/activity` | 누가·언제·무엇을 바꿨는지 |
| 설정 | `#/settings` | 기준일, 우리 상황, 이름, 데이터 내려받기·초기화 |

### 대표 사용자 흐름 (다음 주 유도분만 예정)

1. 온보딩에서 출산 예정일·입원 예정일을 넣고 출산 방법 `유도분만`을 고릅니다.
   → 유도분만 항목 2개의 우선순위가 올라가고, 제왕절개 항목은 "가능성 있음"으로 남습니다.
2. `오늘`에 `임신 37주 6일 · 출산 예정일 D-15 · 입원일 D-7`이 뜨고,
   지금 먼저 할 일에 출산가방·이동 동선·금식 지침이 3~5개로 정리됩니다.
3. `곧 해야 할 일`에 입원·출산 과정 항목(D-7)이 올라옵니다. 출산 중에는 휴대폰을 보기 어려우니 미리 읽는 용도입니다.
4. 출산 후 설정에 출생일을 넣으면 화면이 `생후 n일`로 바뀌고,
   임신 기준 항목은 닫히고 병원 회복·조리원 항목이 앞으로 나옵니다.
5. 며칠 뒤 몰아서 상태를 바꾸고 완료 날짜를 실제 날짜로 고칩니다. 배우자는 `부부 활동 내역`에서 확인합니다.

### 상태 5단계

`확인 전 → 확인했어요 → 준비 중 → 완료 → 해당 없음` (목록에서 아이콘을 누르면 순환)
`완료`로 바꾸면 완료일이 오늘로 채워지고 완료한 사람이 기록됩니다. 완료일은 나중에 고칠 수 있습니다.

### 보유와 수납의 분리

- 육아용품 항목: `이미 있음 / 구매 예정 / 선물 받을 예정 / 대여 예정 / 필요 없음`
- 같은 항목에 `출산가방 / 조리원 가방` 수납 여부를 따로 둡니다. 두 값은 서로 영향을 주지 않습니다.

## 4. 기술 선택

요청서는 Next.js + TypeScript + Tailwind + shadcn/ui 를 우선 검토하라고 했지만,
**의존성 없는 정적 ES 모듈**로 만들었습니다. 이유는 이 저장소의 [AGENTS.md](../AGENTS.md)입니다.

> 빌드 도구나 프레임워크를 추가하지 않습니다. / 새 의존성을 설치하지 않습니다.
> 값은 토큰 변수로만 참조합니다.

프레임워크를 넣으면 저장소 규칙을 어기고, 안 넣어도 이 MVP에 필요한 것
(라우팅·상태·목록 렌더링)은 전부 됩니다. `python3 -m http.server` 하나로 바로 열립니다.

옮겨 갈 때를 위해 구조는 맞춰 두었습니다.

- 뷰는 `render()` / `mount()` 를 가진 모듈 — 컴포넌트로 1:1 대응
- 저장소는 async 어댑터 — 서버 API로 교체 가능
- 콘텐츠는 순수 JSON — 그대로 DB 시드로 사용 가능
- 스타일은 토큰 변수만 소비 — Tailwind `@theme` 브릿지로 바꿔도 값이 갈라지지 않음

### 모바일 최적화

375×667(iPhone SE)과 390×844에서 측정하고 고친 것입니다.

| 항목 | 전 | 후 |
|---|---|---|
| 상태 아이콘 터치 영역 | 32×32 | 48×48 |
| 줄 탭 영역 | 제목 글자만(23px) | 줄 전체(64px) — `.row-title::after` 로 덮고 상태 버튼만 그 위에 |
| 필터 칩 · 아이콘 버튼 · 보조 버튼 | 32~40px | 48px |
| 완료 숨기기 체크박스 | 13×13 | 48px 높이 칩 버튼 |
| 폼 컨트롤 글자 크기 | select 12px, 검색 13px → **iOS 가 초점 시 화면 확대** | 전부 16px |
| 타임라인 고정 영역 | 184px (칩 줄 + 필터 줄) | 128px (칩 줄 + 필터 버튼, 나머지는 패널로 접음) |
| 상태 변경 반응 (356줄 펼친 상태) | 약 600ms — 전체 다시 그림 | 15~20ms — 해당 줄과 구간 숫자만 갱신 |
| 목록 → 상세 → 뒤로 | 맨 위로 돌아감 | 보던 자리로 복원 |

그 밖에

- 탭 하이라이트 제거, `touch-action: manipulation` 으로 더블탭 확대 지연 제거
- 노치·홈 인디케이터 안전영역(`env(safe-area-inset-*)`)을 상단바 좌우와 본문 하단 여백에 반영
- 화면 밖 구간은 `content-visibility: auto` 로 레이아웃·페인트를 건너뜀
- 유형 칩 가로 스크롤에 `scroll-snap`
- 검색은 `type=search` + `enterkeyhint=search`, 엔터로 키보드를 내리고 결과를 봄
- 세로 480px 미만(가로 모드)에서는 상단바를 48px로 줄이고 부제를 감춤
- 홈 화면에 추가했을 때를 위한 `theme-color` · `apple-mobile-web-app-*` · 파비콘

`user-scalable=no` 는 쓰지 않습니다. 손가락으로 확대할 수 있어야 합니다.

### 인터랙션 설계 — 마찰을 없앤 지점

실제로 조작해 보고 측정한 뒤 고친 것들입니다.

**목록 순서를 화면에 머무는 동안 고정합니다.** 우선순위 정렬은 상태가 바뀔 때마다 결과가
달라집니다. 그대로 두면 하나를 완료할 때마다 목록이 다시 늘어서서, 두 번째 탭이 엉뚱한 줄에
떨어집니다. 실제로 홈에서 같은 자리를 다섯 번 누르니 `확인 전 → 확인 전 → 확인 전 →
확인했어요 → 준비 중` 이 나왔습니다. 지금은 화면에 들어온 순간의 순서를 잠그고 완료한 항목도
자리에 남깁니다(`app/src/order.js`). 화면을 떠났다 오면 새로 정렬됩니다.

**목록에서는 원탭으로 완료합니다.** 5단계를 한 버튼으로 순환시키면 완료까지 세 번 눌러야 하고,
한 번 지나치면 `해당 없음` 이 되어 완료 기록이 지워집니다. 원을 누르면 완료를 켜고 끄고,
나머지 단계는 상세에서 고릅니다.

**상세를 열면 `확인했어요` 가 됩니다.** 그 상태는 말 그대로 내용을 봤다는 뜻이라, 손으로 누르게
할 이유가 없습니다. 손이 가는 단계 하나가 통째로 사라집니다. 열람은 활동 목록에 쌓지 않습니다.

**모든 상태 변경에 되돌리기가 붙습니다.** 되돌릴 수 있어야 탭이 빨라집니다. 토스트는 화면을
다시 그려도 살아남도록 `#app` 바깥에 둡니다.

**상세에는 하단 고정 액션이 있습니다.** 읽는 순서(이유 → 시기 → 방법 → 비용 → 출처)는 그대로
두고, 완료 버튼만 항상 손에 닿는 자리에 둡니다.

**온보딩은 날짜 두 개까지만 보여 줍니다.** 상황 여덟 문항은 접어 두고 "건너뛰어도 돼요" 라고
적습니다. 첫 화면에서 시작하기까지 닿습니다.

**한글 라벨에서 mono 를 걷어냈습니다.** 토큰의 mono 는 "숫자·데이터·라벨" 용인데 한글 라벨에도
쓰고 있었습니다. SF Mono 에 한글 글리프가 없어 글자마다 다른 폰트로 떨어져 자간이 어긋납니다.
지금은 숫자만 있는 자리(`.num`, D-day)에만 쓰고, 날짜·개수가 줄줄이 늘어서는 곳은
`font-variant-numeric: tabular-nums` 로 자릿수만 맞춥니다.

**끝낸 일에는 남은 기한 대신 완료한 날을 보여 줍니다.** 다 한 일에 "9. 10." 이 떠 있을 이유가
없습니다. "오늘 완료" 가 알고 싶은 것입니다.

### 시각 위계 — 측정하고 고친 것

렌더된 값을 실제로 재 보니 규칙과 어긋난 곳이 있었습니다.

**채도색 예산.** design-rules 는 화면당 1~2곳인데 홈에서 6곳이 재었습니다(완료 체크 3 +
링크 2 + 활성 탭). 완료 표시를 무채색 체크로, 보조 링크를 `무채색 + ›` 로, 활성 탭을
아이콘만 채도색으로 바꿔 화면당 1~2곳(현재 구간 점·주 버튼·탭 아이콘)으로 돌아왔습니다.
강조를 아꼈으니 남은 채도색이 다시 눈에 띕니다.

**대비.** `--ink-faint`(2.62:1) 가 유형 아이콘에, `--signal`(4.42:1) 이 12px 링크와 '지금'
배지 글자에 쓰이고 있었습니다. 전부 AA 미달이라 아이콘은 `--ink-muted`(4.74:1) 로, 12px
채도색 글자는 무채색으로 바꿨습니다. faint 는 장식(빈 상태 원, 구분점)에만 남습니다.

**중요도 램프.** 필수 89개에 전부 테두리 칩을 두르니 필수가 다섯 줄 연속인 화면에서 칩이
기둥처럼 쌓여 정작 드문 '주의'(28개) 가 묻혔습니다. 지금은 목록에서 필수 = 굵은 글자,
주의 = 테두리 칩, 권장·선택 = 표시하지 않음(없음이 곧 정보) 세 단계입니다. 네 단계 전부는
상세에서 봅니다.

**정렬선과 경계선.** 왼쪽 시작점이 33 / 67 / 97px 세 개였던 것을 구간 머리에 행과 같은
격자를 적용해 33(표시자·상태 원) / 97(제목) 둘로 줄였습니다. 경계선은 전부 8% 한 종류였던
것을 줄 사이 8% / 구획(구간 경계·고정 바) 14% 두 단계로 나눴습니다. 구간 제목은 크기
(20px)로 위계를 만듭니다 — 같은 정렬선을 쓰므로 위치가 아니라 크기가 단계를 말합니다.

**작은 것들.** 16px 미만 아이콘은 획을 1.5px 로(옆 12px 글자보다 무거워 보이지 않게),
탭 하이라이트를 끈 대신 모든 누름에 `:active` 배경을, D-day 숫자는 12→16px, 상단바 부제에
`임신 38주 · 출산 D-14` 를 넣어 스크롤 중에도 핵심이 남습니다.

### 리텐션 설계 — 첫인상 · 적시 제공 · 재방문 기억

경쟁 리서치(임신 앱: Flo·Ovia·What to Expect·베이비빌리·마미톡 / 리텐션 패턴:
Slack unread·Netflix resume·Paired)에서 확인한 사실 위에 설계했습니다.

**이 앱의 복귀 동력 두 가지는 이미 내장돼 있습니다.** ① 임신 주차의 자동 진행(앱이 스스로
만들어내는 새로움) ② 배우자의 활동. 그래서 스트릭·게임화는 넣지 않습니다 — 임신 맥락에서
"놓친 날" 을 실패로 프레이밍하면 불안만 키웁니다.

**첫인상 (온보딩·홈 히어로).** 온보딩 첫 문장을 "출산 예정일 하나로 시작할 수 있어요" 로 —
입력 비용이 낮다는 것 자체가 후킹입니다. 예정일을 넣는 순간 그 자리에서 "지금 임신 38주 ·
출산까지 D-14" 가 계산되어 응답합니다(첫 입력의 즉각 보상). 홈 히어로는 이 카테고리의 수렴된
공식(주차 → 진행감 → 오늘의 콘텐츠 → 할 일)을 따라 주차 아래 40주 진행 바를 둡니다.
바 채움은 예정일 기반 계산이라 콘텐츠 생성이 아니고, 홈의 채도색 예산(진행 바 + 탭 아이콘)
안에 있습니다.

**적시 제공 (사용 중 매력).** 할 일만 쌓으면 앱이 숙제장이 됩니다. 홈에 '이 시기 알아두기' —
지금 구간의 가이드·증상 중 아직 안 읽은 것 2개를 올립니다. 완료 순간에는 체크가 한 번
튀어 오르고(등장 1회), 남은 개수·구간 진행 숫자가 제자리에서 갱신됩니다.

**재방문 기억.** 사람별 방문 시각을 기록하고(6시간 이상 간격 = 새 방문), 재방문 화면을
리서치 권고 우선순위로 구성합니다:
1. 주가 바뀐 첫 방문 → "임신 38주가 됐어요" 카드가 맨 위 (이번 주 알아두기 3개)
2. 지난 방문 이후 배우자가 완료한 것·남긴 메모 (내가 한 일은 내가 아니 배우자 것만)
3. 보던 항목 이어서 보기 (마지막으로 연 항목, 완료됐으면 생략)

**리서치가 제안했지만 보류한 것.**
- 아기 크기 비유(과일·실측 수치): 의료 수치를 임의로 만들지 않는 원칙과 충돌.
  콘텐츠 시트에 주차별 공식 출처 수치가 들어오면 무채색 실루엣 + 타이포 카드로 구현.
- Paired 식 부부 양방향 문답(둘 다 답해야 공개): 실시간 동기화가 없는 로컬 저장에서는
  반쪽짜리가 됨. 부부 동기화(백엔드) 이후의 1순위 기능.
- 완료음·컨페티: 완료 팝 하나로 시작하고, 사용 데이터를 본 뒤 결정.

### 디자인 판단

- 채도색은 `--signal` 하나만, 화면당 1~2곳(현재 구간 표시, 주 버튼, 활성 탭)에 씁니다.
- 상태 5단계는 색이 아니라 **Lucide 원형 아이콘 5종**으로 구분합니다.
- 중요도는 색이 아니라 **테두리와 굵기**로 구분합니다.
- 유형은 **Lucide 아이콘**으로 구분하고, 읽는 이름은 스크린리더용으로 둡니다.

**토큰에 없어서 만들지 않은 것** — `주의`/위험 항목에 쓸 경고색이 토큰에 없습니다.
공용 토큰에 `--warning` 계열을 추가할지 논의가 필요합니다.
지금은 `triangle-alert` 아이콘 + 진한 테두리로만 구분합니다.

## 5. 다음 개발 우선순위

1. **콘텐츠 채우기** — 지금 가장 큰 제약입니다. `요약/왜/어떻게`가 9종 템플릿이라 상세 화면이 비어 보입니다.
   `공식 출처 확인 필요` 122행부터 실제 출처를 붙이고 문구를 항목별로 씁니다.
2. **부부 동기화** — 지금은 기기 한 대의 localStorage입니다. 계정과 가족 단위 저장소가 필요합니다.
3. **리마인드 발송** — 리마인드 날짜는 저장되지만 알림을 보내지 않습니다. 웹 푸시나 캘린더 내보내기.
4. **경험담 원본** — 경험담 21행은 질문만 있고 내용이 없습니다. 다른 부모의 글을 받아 오는 경로가 필요합니다.
5. **비용 기록** — `예상 비용`이 전부 "○○별 상이"라 실제 결제액을 사용자가 적는 칸이 있어야 의미가 생깁니다.
6. **육아용품 개별 항목** — 시트에는 "목록 만들기" 수준만 있고 개별 물품 행이 없습니다.
   보유/수납 분리는 구현돼 있으나 물품 데이터가 있어야 제 역할을 합니다.
7. **접근성 점검** — 명암비와 초점 순서를 실제 보조기기로 확인.
8. **다크 모드** — 토큰에 다크 값이 없어 손대지 않았습니다. 공용 토큰에 추가된 뒤 대응합니다.
9. **실기기 확인** — 측정은 Chromium 모바일 에뮬레이션입니다. iOS Safari 의 주소창 높이 변화와
   `100dvh` 동작, 안드로이드 키보드가 올라올 때의 고정 영역은 실기기로 봐야 합니다.
